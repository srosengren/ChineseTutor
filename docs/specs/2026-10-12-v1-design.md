# ChineseTutor v1 design

- Date: 2026-10-12
- Status: Approved in discussion; pending review of this written spec
- Related: ADR-0002 (repo layout), ADR-0003 (hosting), ADR-0004 (translation deferred),
  ADR-0005 (licensing), ADR-0006 (dictionary sources and word-class model)

## 1. Scope

### What v1 does

- **Input.** Paste into a text box or drop a `.txt` file. Simplified Chinese. Line breaks and
  paragraphs are preserved. Text that is not Chinese (punctuation, Latin, digits) passes
  through without annotation. Traditional-only characters render without pinyin or entries.
- **Reading view.** Text rendered word by word, with two toggles, both on by default:
  - **Pinyin**: tone-marked pinyin under each word, with spoken tones for 一 and 不 (§3.5).
  - **Word boundaries**: a subtle alternating background per word.
- **Word entry.** Tapping a word opens a popover (wide screens) or bottom sheet (narrow
  screens) showing: the word; every reading in dictionary tones; word-class labels (per
  sense where known); senses; measure words; HSK level; and, for multi-character words, the
  component characters, each of which opens its own entry in the same panel with a back
  button. Word-level labels show at the top; per-sense labels show next to their sense.
  Well-known names (CC-CEDICT has about 19k) have entries like any other word.
- **Characters with several readings.** Inside a multi-character word the word decides the
  reading (银行 *yínháng*). A character on its own uses a hand-maintained default (了 → le);
  the panel shows every reading.
- **Persistence.** The last text and the toggle settings are kept in browser storage.
- **Devices.** Desktop and phone browsers; responsive layout.

### Not in v1

Full-text translation (ADR-0004); manual merge or split of words; guessing unknown words
(names CC-CEDICT lacks split into characters); explaining why a tone changed; Traditional
input; offline use or installation (PWA); audio; saved texts or history; keyboard navigation
between words.

### Done when

A graded-reader page or news article pasted in shows words and pinyin within about a second
once the dictionary has loaded, and every word opens an entry when tapped.

## 2. Dictionary data build (`tools/dict-build`)

### When it runs

By hand: `npm run dict:build`. Output is committed to `packages/dict-data/`. CC-CEDICT only
publishes its latest version, so building in CI would not be reproducible; committing the
output makes each data update a reviewable commit and publishes the CC BY-SA data openly
(ADR-0005). Raw downloads go to `.cache/` and are never committed.

### Inputs

| Source | Pinning | Used for |
|---|---|---|
| CC-CEDICT (`cedict_1_0_ts_utf-8_mdbg.txt.gz` from mdbg.net) | Download date and SHA-256, recorded in `docs/data-sources.md` | Headwords, readings, senses, measure words |
| jieba `dict.txt` | Git commit | Word frequency; fallback word class |
| complete-hsk-vocabulary `complete.json` | Git commit | HSK 3.0 level; word-level word classes |

From the HSK list we use only `level` (`new-1` … `new-7`; `new-7` is band 7–9; lowest level
wins) and `pos`. Its definitions are copied from CC-CEDICT and its frequencies come from a
third project with no clear licence, so neither is used. The undocumented `newest-*` levels
are ignored.

### Steps

1. **Parse CC-CEDICT.** Each line `TRAD SIMP [pinyin] /gloss/gloss/` becomes one reading,
   grouped into an entry by the simplified headword. `u:` in pinyin is kept as-is (the
   formatter turns it into ü).
2. **Split glosses.**
   - `CL:個|个[ge4],位[wei4]` becomes `classifiers: [{ word: "个", pinyin: "ge4" }, …]`.
   - Glosses starting `Taiwan pr.` or `also pr.` become reading `notes`.
   - Everything else becomes a sense, text unchanged.
3. **Sense-level word class** where CC-CEDICT's conventions make it certain:
   - Reading pinyin starts with a capital letter, or the gloss starts with `surname ` →
     `proper-noun`.
   - Gloss starts with `to ` → `verb`.
   - Gloss starts with `classifier for` → `measure-word`.
   - Gloss starts with a parenthesis containing the word `particle` → `particle`.
4. **Word-level word class.** The HSK list's tags mapped through §2.1; if the word has no
   HSK tags, jieba's single tag mapped the same way. Possibly empty.
5. **Frequency.** jieba frequency for the headword; `1` if jieba lacks it.
6. **Order readings.** If `default-readings.json` (§2.2) lists the headword, that reading
   comes first. Otherwise the first reading whose pinyin is not capitalised comes first;
   if every reading is capitalised (a proper noun), file order is kept.
7. **Emit** the files in §2.3, then run the build checks (§5.2). The build fails if any
   check fails.

### 2.1 Word-class labels and tag mapping

Labels (`WordClass`): `noun`, `proper-noun`, `verb`, `adjective`, `adverb`, `pronoun`,
`numeral`, `measure-word`, `preposition`, `conjunction`, `particle`, `interjection`,
`onomatopoeia`, `idiom`, `expression`, `time-word`, `location-word`.

Source tags (jieba and the HSK list share the ICTCLAS-style tag set):

| Tags | Labels |
|---|---|
| `n`, `ng` | noun |
| `nr`, `nrfg`, `nrt`, `ns`, `nt`, `nz` | proper-noun |
| `v`, `vd`, `vg`, `vi`, `vq` | verb |
| `vn` | verb, noun |
| `a`, `ag`, `b`, `z` | adjective |
| `ad` | adjective, adverb |
| `an` | adjective, noun |
| `d`, `dg`, `df` | adverb |
| `r`, `rg`, `rr`, `rz` | pronoun |
| `m`, `mg`, `mq` | numeral |
| `q` | measure-word |
| `p` | preposition |
| `c` | conjunction |
| `u`, `ud`, `ug`, `uj`, `ul`, `uv`, `uz`, `y` | particle |
| `e` | interjection |
| `o` | onomatopoeia |
| `i` | idiom |

| `f`, `s` | location-word |

A tag not in this table fails the build.

### 2.3 Output (`packages/dict-data/`)

```
packages/dict-data/
  LICENSE            CC BY-SA 4.0 text
  ATTRIBUTION.md     sources, versions, licences
  data/
    manifest.json
    lexicon.json
    entries/000.json … entries/127.json
```

- `manifest.json`: `{ version, builtAt, shardCount: 128, sources: [{ name, url, pinned, licence }] }`.
  `version` is the first 12 hex characters of a SHA-256 over the lexicon words and all
  entries, computed before the `version` fields are written.
- `lexicon.json`: `{ version, total, words: [[word, frequency, defaultPinyin], …] }`, where
  `total` is the sum of all frequencies and `defaultPinyin` is the first reading's numbered
  pinyin.
- `entries/NNN.json`: `{ version, entries: { [word]: Entry } }`, holding every entry where
  `shardOf(word, 128) === NNN`.

Size budgets (gzip): `lexicon.json` ≤ 1.5 MB; each entry file ≤ 100 KB; all entry files
together ≤ 6 MB. Measured on 2026-10-12 data: 121,499 headwords, lexicon about 1.1 MB,
entries about 4.2 MB.

### 2.4 Tech

Plain TypeScript run directly by Node 24 (built-in type stripping; no compile step). Imports
`shardOf` and the data types from `packages/core`, so the build and the app always agree.

## 3. `packages/core`

### 3.1 Constraints

- Pure TypeScript. Its tsconfig has `lib` without DOM and `types: []`.
- No dependencies at all; a test fails if a `core` file imports a package (§5.1).
- Erasable syntax only (`erasableSyntaxOnly`), so Node can run it: no `enum`, no namespaces,
  no parameter properties.
- Relative imports use explicit `.ts` extensions. Shipped as source; Vite, Metro and Node
  consume it directly.

### 3.2 Types

```ts
type WordClass =
  | 'noun' | 'proper-noun' | 'verb' | 'adjective' | 'adverb' | 'pronoun' | 'numeral'
  | 'measure-word' | 'preposition' | 'conjunction' | 'particle' | 'interjection'
  | 'onomatopoeia' | 'idiom' | 'expression' | 'time-word' | 'location-word';

interface Entry {
  word: string;               // simplified headword
  readings: Reading[];        // default reading first
  wordClasses: WordClass[];   // word level; may be empty
  hskLevel?: number;          // HSK 3.0: 1–6, 7 = band 7–9
}

interface Reading {
  pinyin: string;             // numbered syllables, e.g. "xue2 xi2"; capitalised for names
  traditional: string;
  senses: Sense[];
  classifiers: Classifier[];
  notes: string[];            // e.g. "Taiwan pr. [da3]"
}

interface Sense {
  gloss: string;
  wordClasses?: WordClass[];  // sense level; sparse in v1
}

interface Classifier {
  word: string;               // simplified
  pinyin: string;             // numbered
}
```

The entry panel always shows `Entry.wordClasses` at the top, and `Sense.wordClasses` next
to the senses that have them. Moving to per-sense word class later only fills
`Sense.wordClasses` (ADR-0006).

### 3.3 API

```ts
createLexicon(data: LexiconData): Lexicon
segment(text: string, lexicon: Lexicon): Token[]
annotate(tokens: Token[]): AnnotatedToken[]
formatPinyin(syllables: string[]): string
createEntryStore(loadShard: (index: number) => Promise<EntryShard>, options: { shardCount: number; version: string }): EntryStore
shardOf(word: string, shardCount: number): number

type Token =
  | { kind: 'word'; text: string; start: number; pinyin: string }  // default reading, numbered
  | { kind: 'unknown'; text: string; start: number }               // one Chinese character
  | { kind: 'other'; text: string; start: number };                // anything else, verbatim

type AnnotatedToken = Token & { syllables?: Syllable[] };          // set on word tokens

interface Syllable {
  dictionary: string;        // numbered, e.g. "yi1"
  spoken: string;            // numbered, e.g. "yi2"
  rule?: ToneRule;           // set when spoken differs from dictionary
}

type ToneRule = 'bu-before-fourth' | 'yi-before-fourth' | 'yi-before-other';

interface EntryStore {
  lookup(word: string): Promise<Entry | undefined>;
  prefetch(words: Iterable<string>, maxShards: number): void;
}
```

- `shardOf`: FNV-1a 32-bit over the word's UTF-16 code units, modulo `shardCount`.
- `EntryStore` caches loaded shards and shares in-flight loads, so a shard is never fetched
  twice concurrently. A failed load is not cached: the next lookup retries. If a shard's
  `version` differs from `options.version` (the manifest's), `lookup` rejects with a
  `DataVersionMismatch` error.

### 3.4 Segmentation

1. Split the text into runs of Chinese characters (`\p{Script=Han}`) and runs of everything
   else. Every non-Chinese run becomes one `other` token.
2. For each Chinese run, build a DAG: from each position, every lexicon word starting there
   (up to the lexicon's longest word).
3. Every position also has a one-character step. If that character is not itself a
   lexicon word, the step has frequency 1 and is emitted as an `unknown` token.
4. Dynamic programming from the end of the run picks the path that maximises the sum of
   `log(frequency / total)`.
5. Emit `word` tokens carrying the lexicon's default pinyin.

Targets, checked by a benchmark script (not gating CI): `createLexicon` for the full lexicon
≤ 150 ms and `segment` on 20k characters ≤ 50 ms, on a desktop machine.

### 3.5 Tone changes for 一 and 不

`annotate` walks the syllables of consecutive `word` tokens as one *phrase*; an `other` or
`unknown` token ends the phrase. "Next syllable" means the next syllable in the same phrase,
across word boundaries, using its **dictionary** tone. The rules apply only to syllables
whose dictionary value is `bu4` or `yi1`.

**不 (`bu4`)**
- Unchanged if the characters on both sides are the same (A不A: 好不好).
- `bu2` (`bu-before-fourth`) if the next syllable has tone 4.
- Otherwise unchanged.

**一 (`yi1`)** is unchanged if any of these holds:
- it has no next syllable in the phrase;
- it is the last character of a multi-character word (统一, 唯一, 第一, 十一, 星期一);
- the previous character is 第 or one of 〇零一二三四五六七八九十;
- the next character is one of 〇零一二三四五六七八九十, or 月 or 号;
- the characters on both sides are the same (A一A: 看一看);
- the next syllable has tone 5.

Otherwise it is `yi2` (`yi-before-fourth`) before tone 4 and `yi4` (`yi-before-other`)
before tones 1–3.

| Input | Expected spoken pinyin |
|---|---|
| 不是 | bú shì |
| 不要 | búyào |
| 不好 | bù hǎo |
| 好不好 | hǎo bù hǎo |
| 一个 | yí gè |
| 一天 | yì tiān |
| 一年 | yì nián |
| 一起 | yìqǐ |
| 一样 | yíyàng |
| 一百 | yìbǎi |
| 第一 | dìyī |
| 十一 | shíyī |
| 一月 | yīyuè |
| 一二三 | yī èr sān |
| 统一思想 | tǒngyī sīxiǎng |
| 看一看 | kàn yī kàn |
| 我有一。 | wǒ yǒu yī |

The expected values assume CC-CEDICT's citation pinyin for each word; the test table is
adjusted if the data segments an input differently.

### 3.6 Pinyin formatting

`formatPinyin` turns numbered syllables into tone marks and joins one word's syllables:

- Mark placement: on `a` or `e` if present; on `o` in `ou`; otherwise on the last vowel.
- `u:` and `v` become `ü` (`nu:3` → `nǚ`, `lu:e4` → `lüè`).
- Tone 5 has no mark. `r5` after a syllable attaches as erhua (`hua4 r5` → `huàr`).
- Capitalisation is preserved. CC-CEDICT capitalises each part of a name, so a capitalised
  syllable after the first starts a new written word: `Xi2 Jin4 ping2` → `Xí Jìnpíng`,
  `Zhou1 Jie2 lun2` → `Zhōu Jiélún`, `Shang4 hai3` → `Shànghǎi`.
- An apostrophe precedes a non-initial syllable starting with `a`, `e` or `o`
  (`xi1 an1` → `xī'ān`).

The reading view formats `spoken` values; the entry panel formats `dictionary` values.

## 4. Web app (`apps/web`)

### 4.1 Stack

React + Vite + TypeScript. Plain CSS with custom properties; light and dark themes from
`prefers-color-scheme`. Chinese font stack: `"PingFang SC", "Noto Sans SC", "Microsoft
YaHei", sans-serif`. No UI component library, no state library, no router.

### 4.2 Screens

One page, two modes:

- **Input mode.** A text box and a drop zone for `.txt` files, plus a **Read** button
  (disabled while the text is empty). Usable while the dictionary loads.
- **Reading mode.** A header with the **Pinyin** and **Word boundaries** toggles and an
  **Edit text** button, then the rendered text.

### 4.3 Reading view

- Paragraphs: the text is split on newlines into `<p>` elements.
- Each `word` token is `<ruby>学习<rt>xuéxí</rt></ruby>` with `ruby-position: under`, plus a
  `data-i` index. `unknown` tokens render the same way without `<rt>`. `other` tokens are
  plain text.
- Toggles flip a class on the container (`.hide-pinyin`, `.show-boundaries`); they never
  re-render the text. Boundaries alternate between two background shades by token parity.
- One click listener on the container resolves the tapped token from `data-i`.

### 4.4 Entry panel

- At 640 px and wider: a popover anchored below the word (above if there is no room).
  Narrower: a bottom sheet. Closed by Escape, a tap outside, or a close button.
- Content, top to bottom: headword; then for each reading: pinyin (dictionary tones),
  traditional form if different, notes, senses (each with its own word-class labels if
  set), measure words; then the word-level word-class labels, the HSK level, and the
  component characters as buttons.
- Tapping a component character pushes its entry onto a stack in the panel; **Back**
  pops it.
- States: loading; entry; "Not in dictionary" (unknown tokens and lookups that find
  nothing); error with **Retry**; "Dictionary updated" with **Reload** on
  `DataVersionMismatch`.

### 4.5 Data loading

- The build copies `packages/dict-data/data/` into the build output as `data/`.
- On start: `fetch('data/manifest.json', { cache: 'no-cache' })`, then
  `data/lexicon.json?v=<version>`, then `createLexicon`. If the lexicon's `version` differs
  from the manifest's (a deploy landed between the two requests), fetch both again once.
- `createEntryStore` with the manifest version and a loader fetching
  `data/entries/NNN.json?v=<version>`.
- After a text renders, `prefetch` the words in it with `maxShards: 32`.
- GitHub Pages serves gzip with `Cache-Control: max-age=600` and ETags, so a repeat visit
  revalidates rather than re-downloads.

### 4.6 Persistence

`localStorage` keys `chinese-tutor:text` and `chinese-tutor:settings`. Every read and write is
wrapped in `try/catch`; when storage is unavailable or full, the app works without it.

### 4.7 Attribution

A footer link opens an **About & sources** panel listing CC-CEDICT, jieba and
complete-hsk-vocabulary with their licences and links, generated from `manifest.json`.

### 4.8 Deployment

GitHub Actions workflow on push to `main` and on pull requests:

1. `npm ci`
2. `npm run typecheck`
3. `npm test`
4. `npm run build -w apps/web` (Vite `base: '/ChineseTutor/'`)
5. On `main` only: upload the build as the Pages artifact and deploy.

## 5. Testing and error handling

### 5.1 Automated tests

Node's built-in test runner (`node --test`) runs `.ts` test files directly; there is no test
framework dependency. Tests live in each workspace's `test/` folder with their own tsconfig
that includes Node types; `packages/core/src` stays free of them. `npm test` runs every workspace's tests; `npm run typecheck` runs
`tsc --noEmit` per workspace.

`packages/core`:
- **Segmentation (algorithm):** a small hand-made lexicon for edge cases: 研究生命起源 →
  研究/生命/起源; 南京市长江大桥 → 南京市/长江/大桥; mixed text `2026年我在Paris。`; unknown
  characters; empty input.
- **Segmentation (real data):** at least 50 hand-checked sentences across HSK levels, run
  against `packages/dict-data`. Expected splits follow CC-CEDICT's word list. Catches
  regressions when the dictionary is updated.
- **Tone rules:** the table in §3.5.
- **Pinyin formatting:** every rule in §3.6.
- **Entry store:** caching, shared in-flight loads, prefetch cap, failed loads retried,
  version mismatch.
- **`shardOf`:** fixed expected values for a handful of words.
- **Platform guard:** no file under `packages/core/src` imports a package.

`tools/dict-build`:
- **Parser:** lines with measure words, variants, `u:`, Taiwan pronunciation notes,
  capitalised names, and `surname` senses.
- **Sense heuristics:** each rule in §2, step 3.
- **Tag mapping:** every tag in §2.1 maps or is dropped; an unknown tag throws.

### 5.2 Build checks (run by every `npm run dict:build`)

- 学习 has default pinyin `xue2 xi2`; 了 defaults to `le5`; 银行 to `yin2 hang2`;
  习近平 has a `proper-noun` sense.
- Entry count between 100,000 and 150,000.
- Fewer than 0.1% of CC-CEDICT lines fail to parse.
- Every `default-readings.json` reading exists.
- Size budgets in §2.3.

### 5.3 Manual checklist (web)

1. Paste an HSK 1 dialogue, a news paragraph, and text mixing Latin, digits and punctuation.
2. Toggle pinyin and word boundaries.
3. Tap a word, an unknown character, and a component character; use Back.
4. On a phone-width viewport: the bottom sheet opens and closes.
5. Dark mode.
6. Reload: text and toggles persist.
7. With the network offline: the dictionary error and Retry work; an entry error and Retry
   work.
8. Drop a UTF-8 `.txt` file and a GB18030 `.txt` file.

### 5.4 Error handling

| Situation | Behaviour |
|---|---|
| Manifest or lexicon fails to load | Message with **Retry**; input mode still works; **Read** waits for the dictionary. |
| An entry file fails to load | Panel shows error with **Retry**; the failure is not cached. |
| Data version changed mid-session | Panel shows "Dictionary updated" with **Reload**. |
| Dropped file is not `.txt` | Message: only `.txt` files are supported. |
| `.txt` is not valid UTF-8 | Decode with `TextDecoder('utf-8', { fatal: true })`; on failure retry with `gb18030`. |
| Text longer than 100k characters | Truncated to 100k with a message. |
| Text with no Chinese | Renders as plain text. |
| Browser storage unavailable or full | Ignored silently. |

## 6. Repository changes

- New workspaces: `packages/core`, `packages/dict-data`, `tools/dict-build`, `apps/web`.
- Root `package.json` scripts: `dev`, `build`, `test`, `typecheck`, `dict:build`.
- TypeScript is a root dev dependency. A shared `tsconfig.base.json` has `strict`,
  `erasableSyntaxOnly`, `verbatimModuleSyntax`, `allowImportingTsExtensions` and `noEmit`.
- `npm run dict:build` writes `docs/data-sources.md` and `packages/dict-data/ATTRIBUTION.md`
  from the manifest's `sources`, so the recorded versions always match the committed data.

## 7. Risks to check early

- **Node type stripping across the workspace link.** Node will not strip types for files
  under `node_modules`. npm links `packages/core` into `node_modules`, and Node resolves
  symlinks to their real path by default, so this should work. Verify in the first
  implementation task.
- **`<ruby>` rendering of long texts on phones.** If 20k characters render slowly, render
  paragraphs progressively. Measure before optimising.
